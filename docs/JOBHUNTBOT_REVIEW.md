## 实际定位

JobHuntBot 不是岗位抓取、匹配或自动提交引擎。它由 Agent 工作流说明、候选人配置模板、空白 CSV 和本地 Node 看板组成。看板已在空白数据上成功运行，且不需要 npm 安装。

## 值得吸收的设计

- 岗位池、申请中、已投递和已结束的完整流程
- 只有看到感谢页、确认编号等证据才计为已投递
- 验证码、身份、工作资格、薪资等问题转人工处理
- 记录卡点原因、下一步和招聘阶段
- 面试、笔试与跟进日程
- 候选人事实、答案库、经历库和简历版本路由的分层思想

## 没有直接合并原代码的原因

- 原始看板把 CSV 中的岗位 URL 插入 HTML 时未完整转义，也未限制 URL 协议，存在不安全链接和存储型脚本注入风险。
- 本地写接口没有 CSRF/Origin 校验。
- 两个 CSV 的更新不是事务操作，也没有文件锁或备份。
- 同一公司的多个岗位只按公司名关联，可能串联错误记录。
- 工作流中的最终提交确认是文字约定，不是程序强制门禁。

因此，外部目录保持原样、使用空白数据，只作为参考；真实数据继续使用当前应用的 SQLite 和稳定的 `source + job_id` 关联。

## 已在当前 App 中重新实现

- 投递状态看板：待复核、已确认、已打开、卡点、已投递、Offer、未通过、跳过
- 提交证据门禁
- 卡点、备注、下一步和当前阶段
- 未来 7 天日程及完成/取消状态
- SQLite WAL、超时和旧数据库迁移
- 关键词边界与常见中英文别名
- CSV 公式注入防护

- 更严格的隐私忽略规则

没有移植 OTP 读取、默认批量模式或自动最终提交。
